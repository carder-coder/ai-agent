1. `src/agent/tools/fs.py` 的 `SearchFilesArgs` 增加 `summary: bool = False`；为真时只返回按文件计数与总数，不带上下文行。
2. `src/agent/loop/agent_loop.py` 的系统提示补一条：统计类任务先用 summary 取汇总，再用 limit 取明细，总数只认 summary 给出的数字。

```powershell
python -m uv run python -m agent.cli --task "统计本仓库 TODO 与 FIXME 数量并列出前十条" --max-steps 12
```

- 步数不超过 6；总数与 trace 里 tool 事件返回的 total 一致。

## 任务二：工具边界与退避单测（1.5 小时）

四条断言：

1. `run_shell` 输出超过 4000 字符时，结果里必须出现"已截断"标记。
2. `search_files` 命中超过 limit 时，返回头写"命中 N 行"，尾部写"只列前 M 条"。
3. 拒绝执行（`rm`、`git push`）返回 `ok=False`，message 以"拒绝执行："开头。
4. 本地 429 桩驱动真实客户端：前两次返 429 JSON、第三次返带 usage 的 SSE，断言 `attempts==3` 且间隔为 `[1.0, 2.0]`。

```powershell
python -m uv run pytest -q
python -m uv run ruff check .
```

验收标准：

- pytest 不少于 15 条且全绿；ruff 0 问题。
- 四条断言在故意改坏实现时都能指出具体字段，而不是只报"断言失败"。

## 任务三：trace 重放器（1 小时）

`scripts/replay.py`，参数 `--trace traces/<文件>.jsonl`，输出三段：

- 头部：run_id、步数、stop_reason、总耗时。
- 每步：序号、工具名、参数（截断 80 字）、工具耗时、本步 token 与成本。
- 尾部：总 token、总成本，以及与 `run_end` 事件的差值。

对三份 trace 各跑一次：`20261107-150042-a215a8`（7 步成功）、`20261107-145806-d35f48`（撞上限）、`20261107-181417-b913a0`（8 步、新计价）。

验收标准：

- 三份都能跑完，总成本与 `run_end` 一致，差值 0。
- 撞上限那份能打印 stop_reason 与最后一步的工具名，而不是抛出异常。
- 字段缺失时打印"字段缺失：xxx"，不静默跳过。

## 任务四：真实限流压测（1 小时）

`scripts/press_429.py`：`ThreadPoolExecutor` 8 并发、每路 20 次，同一短提示、`max_tokens=16`，记录每次的 ok、错误码、耗时、attempts、退避间隔。

退出码约定：出现 429 且退避生效返回 0；出现 429 但间隔不在 1、2、4 秒返回 2；全程没触发 429 返回 3。

验收标准：

- 至少出现一次 429。
- 命中 429 的那次 `attempts > 1`，间隔落在 1.0、2.0、4.0 秒的正负 0.2 秒内。
- 脚本不抛未捕获异常，退出码能被 CI 直接判断。

## 任务五：系统提示 A/B（1.5 小时）

验收标准：

- 两版都不超 12 步；结论里写清适用条件是"统计类"还是"全部任务"。
