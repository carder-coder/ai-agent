## 持续压测

在进程内启动 `api.NewRouter`，配置 `mock` Provider 和 200 并发上限，通过 loopback `httptest` 对 `/healthz` 进行 GET 请求。该路径不调用模型服务、不写工具审计 trace；本次只衡量网关 HTTP 健康检查路径，不代表聊天接口或模型上游的容量。

| 指标 | 结果 |
| --- | ---: |
| 持续时间 | 30 分钟 |
| 配置并发 / 实测峰值并发 | 200 / 200 |
| 请求数 | 15,519,281 |
| 成功数 | 15,519,082 |
| HTTP / 请求错误数 | 0 |
| 截止时取消数 | 199 |
| 成功请求错误率 | 0% |
| 吞吐 | 约 8,621.8 请求/秒 |
| P50 / P95 / P99 | 11.50 / 78.50 / 134.40 毫秒 |

199 个取消请求是压测截止时仍在途的请求，不计为 HTTP 错误；延迟分位数使用 0.1 毫秒宽度的有界直方图。压测由临时 `go test` harness 执行并在测试后移除，完整输出显示 30 分钟运行通过。

持续压测 CLI (`--duration`) 限定为明确的 localhost / loopback IP，最多 200 并发、最长 30 分钟，避免将长时间压测误发到非本机目标。固定请求数模式仍默认 POST，也可通过 `--method` 明确选择 GET / POST。
