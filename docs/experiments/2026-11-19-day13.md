### 1. multi-tool-01 / window：早期证据被整轮丢弃

任务：先读 `pyproject.toml` 确认 Python 版本，再读 `README.md` 核对运行环境并比较。
期望：分别读取两个文件并给出一致/不一致结论。

第 4 步的 `llm` 事件：

```text
上下文: window 保留 7/10 条，丢弃 3
被裁: index 0, tool=read_file、search_files, chars=2524
      "我会先读取 pyproject.toml... [pyproject.toml] 共 41 行 ... requires-python = \">=3.13\""
```

被裁的正是第一轮 `read_file pyproject.toml` + `search_files README` 的结果。此后第 5 至 12 步
`dropped_detail` 里 index 0 一直是这一轮，模型反复重读 pyproject/README，直到步数耗尽。
`window(2)` 只保留最近两轮，结论所需的早期证据永远回不到上下文。

### 2. multi-tool-03 / retrieval：预算不足以容纳最近轮，高分片段也进不来

任务：找到 `DoubaoClient` 的超时异常映射代码，检查对应测试并报告测试名称。
第 3 步 `context.retrieval`：

```json
{"budget": 3000, "chars": 7300, "used": 4, "total": 7,
 "selected": 0, "dropped": 1, "over_budget": true,
 "scores": {"0": 2.781}, "selected_indexes": []}
```

`dropped_detail` 显示被裁的是首轮搜索结果（`src/agent/llm/doubao.py:24: class DoubaoClient`，
BM25 2.781）。原因不是分数低，而是"锚点 + 最近一轮（读了 152 行 doubao.py）"已经 7,023 字符，
超过 3,000 预算，任何候选都加不进去。之后模型反复搜索/读取同一文件，最终无结论。
这是检索粒度与预算共同造成的失败：最近轮不可拆，预算又按整轮判断。

### 3. multi-tool-03 / summary：摘要丢掉函数名，且被 `max_tokens` 截断

同一任务在 summary 策略下，第 3/5/6/7/8/9/10/11/12 步都生成了摘要，但摘要文本始终没有出现
期望的测试名 `test_read_timeout_is_mapped_to_provider_timeout`。例如第 5 步摘要：

```text
已读 src/agent/llm/doubao.py（共 152 行）：DoubaoClient 类位于第 24 行；
环境变量包括 ARK_API_KEY、ARK_MODEL... 默认 timeout 为 60、max_retries 为 3...
```

第 8、12 步 `finish_reason=length`，摘要被截断；第 10/11 步把 `tests/test_llm.py` 列进"相关文件"，
却没有保留测试函数名。模型拿到的早期信息被压缩成"文件/类/参数"，关键标识符丢失，于是继续搜索，
12 步后仍无结论；本次 75,673 token、0.043173 元，是四个案例里最贵的。

### 4. multi-tool-04 / summary：空摘要触发降级，随后被 window 截断

任务：查看 README 中的测试命令，再检查 `tests/` 下有哪些测试模块并整理清单。
第 3 步摘要两次尝试均返回空正文，`trace` 记录：

```text
summary_error: step=3, attempts=2, finish_reason=length,
usage={in:6270, out:2400, total:8670}, cost=0.010288
error="摘要模型返回空内容（finish_reason=length，尝试 2 次）"
```

摘要按设计在本任务内停用并降级 `window(2)`，但滑窗随后丢掉了早期读到的 README/测试清单，
模型重读目录，12 步 max_steps。该案例说明降级路径虽然避免了任务崩溃，但"失败后改用滑窗"
仍会丢证据；失败摘要本身的 2,400 输出 token 也照价计入了成本。

## 共同原因

1. **预算/阈值按字符估算，且小于真实上下文**：本任务集 `full` 多数请求只有几千字符，
   3,000 的预算/阈值对"锚点 + 最近轮"都可能不够，裁剪从第一轮有效证据开始。
2. **整轮裁剪粒度过粗**：`window`/`retrieval` 以"assistant + 全部 tool 结果"为单位，
   不能保留一轮中的关键片段，也不能裁掉一轮中的噪声。
3. **摘要丢标识符、被截断**：固定提示要求压缩，但没有强制保留函数名/路径等精确标识符；
   `max_tokens=800`（重试 1600）在长输入下会 `finish_reason=length`。
4. **失败降级仍是丢信息**：摘要失败切 window 只能保证继续运行，不能保证证据还在。
