### 两种策略

- `full`：把全部 `messages` 发给模型，保持第 1 周行为，是默认值。
- `window`：保留开头的 system 与首条 user 作为锚点，再保留最近 N 轮；一轮 = 一条 assistant
  响应及其全部 tool 结果，整轮保留或整轮丢弃，避免出现没有父调用的孤立 tool 消息。
  无法归属到任何一轮的孤立消息直接丢弃，作为兜底。

滑窗只作用于"本次请求的消息"；断点、恢复、重复检测和工具回填仍基于全量对话。
断点新增 `context_strategy` / `context_window` 两个可选字段，旧断点缺字段时按 `full` / 4 读取。

## 验收：同一批任务跑两种策略

用 `scripts/run_cases.py` 对每类取第一条（`--sample-per-category 1`），同一批 4 条任务分别跑
`full` 与 `window`（窗口 2，便于在 2 至 3 步的任务里触发裁剪），模型同为
`doubao/deepseek-v4-1-flash-economy-261017`，步数上限 8：

| 用例 | 类别 | full 停止原因 / 步数 / token / 成本 | window(2) 停止原因 / 步数 / token / 成本 |
| --- | --- | --- | --- |
| `single-qa-01` | single_qa | finished / 2 / 4,436 / 0.002453 元 | finished / 7 / 18,348 / 0.010091 元 |
| `multi-tool-01` | multi_tool | finished / 3 / 9,734 / 0.007911 元 | no_tool_call / 2 / 4,670 / 0.003275 元 |
| `long-read-01` | long_read | finished / 2 / 5,630 / 0.006383 元 | finished / 2 / 5,252 / 0.003668 元 |
| `refusal-01` | refusal | no_tool_call / 4 / 6,574 / 0.004622 元 | finished / 2 / 4,010 / 0.005685 元 |
| 合计 | — | 3/4 finished，26,374 token，0.021369 元 | 3/4 finished，32,280 token，0.022719 元 |

两批均无异常，同一批任务两种策略都能跑完，验收达成。原始记录（被忽略目录）：
`out/day9_full.jsonl`、`out/day9_window.jsonl`。

窗口裁剪的实际证据（`window` 的 `single-qa-01` trace）：

```text
步骤 4: ... 上下文: window 保留 6/8 条，丢弃 2
步骤 6: ... 上下文: window 保留 6/12 条，丢弃 6
步骤 7: ... 上下文: window 保留 6/14 条，丢弃 8
```

即锚点（system + 任务）始终保留，被丢弃的是更早的工具交互轮次；`full` 同任务每步保留条数为 2、4。

## 验证

```powershell
uv run python -m agent.cli --task "..." --context-strategy window --context-window 2
uv run python scripts/run_cases.py --strategy full --sample-per-category 1
uv run python scripts/run_cases.py --strategy window --window 2 --sample-per-category 1
uv run python scripts/replay.py --trace traces\<run_id>.jsonl
uv run pytest -q
uv run ruff check .
```

- 单测 46 条全过，`agent.context` 覆盖裁剪边界、工具配对、CLI 切换与恢复继承。
- `ruff check .` 无问题。
- 两策略跑同一批 4 条任务：达成。

## 观察（样本仅 4 条，不下结论）

- `single-qa-01` 在 `window(2)` 下用了 7 步、token 也更高：旧工具结果被裁掉后，模型重复读了
  README 与 pyproject。这可能是"证据被裁导致重复取证"，也可能只是单次采样波动，需要 11-18 的
  50 × 4 矩阵才能判断。
- `multi-tool-01` 在 `window` 下第 2 步直接文本回答，记为 `no_tool_call`；`refusal-01` 在 `full`
  下多走了两步。两类都不是异常退出，但说明"成功"不能只看是否 `finished`，11-18 需要按类别
  定义成功率。
- 本日只验证"能跑同一批任务"，不比较优劣；窗口单位是"轮"而不是 token，预算控制留给摘要与检索。

## 遗留
