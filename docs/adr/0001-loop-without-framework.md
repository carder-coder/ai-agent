# ADR 0001：循环自己写，先不引框架

- 状态：已采纳
- 日期：2026-11-07
- 阶段：阶段一第 1 周

## 背景

A1 需要一个能带工具调用跑通任务的最小智能体。可选路径有两条：直接引入 LangGraph 或 eino，
或者用 300 到 400 行自建循环。后续阶段三、四要接检索与 MCP，阶段六还要做框架对比。

## 决策

第一周自建循环。框架选型推迟到阶段六，届时用同一份评测集做对比，而不是凭文档选。

理由：

1. 循环的四个动作（问模型、执行工具、回填结果、判断停）在没有框架时也只有一屏代码，
   先看清每一步的输入输出，后面对比框架才有基准。
2. 框架的隐藏状态会掩盖两类关键问题：上下文超限和工具返回值污染。这两类恰是后面成本与
   可靠性工作的主要来源。
3. 自建循环的 trace 格式由自己定，阶段五的评测可以复用同一套事件。

## 后果

- 正面：状态机、trace、成本计量三件事可以一起设计，不用迁就框架抽象。
- 负面：多智能体编排需要自己搭，阶段六如有必要会补一层薄封装。
- 触发复核：若 A4 的检索循环代码量超过 800 行，重新评估是否引入框架。
